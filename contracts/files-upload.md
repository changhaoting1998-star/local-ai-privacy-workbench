# Personal file extraction contract — files-r1

Frozen endpoint: `POST /api/files/extract`, existing pg_auth cookie + `X-CSRF-Token`, allowed Origin. Multipart/form-data exactly one field named `file`. No session id, no automatic preview/send. Files only personal loopback profile; LAN returns files_personal_only.

Accepted .pdf (application/pdf), .docx (application/vnd.openxmlformats-officedocument.wordprocessingml.document), .xlsx (application/vnd.openxmlformats-officedocument.spreadsheetml.sheet); application/octet-stream accepted only when extension and magic/package agree. .doc/.xls rejected with save-as guidance. One file <=10 MiB; whole multipart <=10 MiB+64 KiB, max 20,000 Unicode code points including location labels. No truncation. Request is streamed and bounded before parsing; worker timeout 45 seconds, max 2 workers, 768 MiB aggregate process-group resident memory budget checked every 250 ms, no persistent upload records. Worker uses minimal environment, Python socket audit denial, CPU40s, FD64, core disabled; necessary native shader caches may write inside unique0700 TMPDIR/HOME, per-file32MiB cap, recursive cleanup on success/error/timeout. Application never writes original bytes/rasters there; native OCR behavior and caches remain platform dependent.

200 JSON: `{ "text": "[第1页 · PDF文字]\\n...", "format": "pdf", "character_count": 123, "coverage": {"complete":true,"summary":"...","units":1,"ocr_used":false}, "warnings": ["..."], "limits": {"file_bytes":10485760,"text_characters":20000} }`. No original filename anywhere in response. `text` is complete reviewable content with source labels. Sheet names and document metadata, when extracted, occur ONLY inside text, then go through existing masking; never use separate filename/sheet metadata in messages/outbound. `coverage.complete` true means all supported text parts were read. Ordinary logos, pictures/charts, or unknown passive parts may return false together with `coverage.requires_acknowledgement:true` and explicit nonempty warnings. The UI MUST require explicit acknowledgement “仅使用已提取内容” before preview; unextracted parts are neither protected nor sent. Macros, active/embedded content, external data fetch relationships, corruption, encryption and resource breaches remain hard errors. Both complete and partial results require human review; success does not promise OCR accuracy or original visual fidelity. UI shows warnings and extracted text for mandatory human review; user may edit; existing preview/confirm/send/restore unchanged. Upload is neither model send nor format-preserving export. Client should clear invalidated preview before upload, cancel fetch on replacement/cancel, ignore stale response and clear file picker.

Errors use existing `{detail:{code,message}}`, with safe fixed messages, never raw text/path/name. Status 401 login_required, 403 csrf/origin/files_personal_only, 413 file_too_large/text_too_large/archive_limits/document_limits, 415 file_type/legacy_format, 422 file_invalid/file_encrypted/unsupported_content/no_readable_text/ocr_unavailable, 429 extraction_busy, 503 extraction_failed, 504 extraction_timeout. A rejected file returns no partial text. Client can display server message as text only. Every error requires choosing another file or manual paste. Source file is not retained; extracted raw text lives in browser/server request memory until explicitly previewed through the existing masking workflow. Encrypted mappings follow the existing 24h policy; only masked messages persist after send. OS swap/snapshots are outside the application deletion guarantee.

Resource caps: ZIP <=2000 entries, expanded <=40 MiB, each entry <=15 MiB, each expansion ratio <=150, no traversal/duplicate/encrypted/symlink entries; PDF <=40 pages and raster size <=12 megapixels per page; OOXML <=30 sheets / 100,000 nonempty or serialized cells / 500,000 XML elements. PDF scans/mixed pages use local Mac Vision with full page OCR in addition to text. Attachments, forms, annotations, active content are rejected conservatively; all reachable PDF streams have 15MiB per-stream and40MiB cumulative decoded caps before native rendering, images <=12MP, object count/depth bounded; OCR is fallible and requires review. DOCX text/tables/headers/footers/footnotes/endnotes/comments and properties are included; pictures/drawings and passive unknown parts yield explicit partial coverage; embedded/active content rejected. External hyperlinks are displayed as literal reviewable text and never visited. DOCX table coordinates use XML row/cell positions (merged layout not reconstructed). XLSX all sheets (including hidden), serialized hidden rows/cells, strings/numbers/booleans/errors/formulas and comments included; formulas displayed literally, never executed; external data connections/embedded/active content rejected; hyperlinks displayed literally and never visited; drawings/images/passive unknown parts produce explicit partial coverage. Standard old and modern comments are read. Shared/array/data-table formulas are conservatively rejected because their expanded formulas are not reconstructed. Dates/numbers use stored values; merge layout and styling are not reproduced. Rich layout fidelity unsupported.

Authenticated GET `/api/files/capabilities` reports enabled/formats/local_ocr (executable installed; runtime OCR is checked per PDF), limits and original_format_export=false. Missing or failing OCR: text-only PDF may yield explicit partial coverage; scanned/image PDF fails with ocr_unavailable. No NER/model accuracy claim.
